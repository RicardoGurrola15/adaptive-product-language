# Component rules

Use the component’s job and state, not just its visible string.

| Component | Required language behavior |
|---|---|
| Button/CTA | Start with an action verb; name the outcome when ambiguity is possible; match the actual event. |
| Link | Describe the destination or next step; do not use repeated “Learn more” without context. |
| Field label | Name the value requested; do not rely on placeholder text as the label. |
| Placeholder | Show format or an example only; never carry essential instructions or the only label. |
| Helper text | Explain constraints before submission; avoid repeating the label. |
| Validation | Identify the field/problem and the next recovery action; preserve entered data where possible. |
| Alert/toast | State what happened, consequence, and available action; do not disappear before users can act when material. |
| Empty state | Explain why it is empty only when known, then offer the next useful action. |
| Loading state | Set expectation without claiming completion; use progress language only when measurable. |
| Confirmation | Confirm the actual result, not merely a click; mention next step or undo when available. |
| Destructive dialog | Name the irreversible consequence and make cancel/equivalent easy to find. |
| Pricing card/paywall | Show price unit, cadence, eligibility, limits, renewal or one-time nature, and a non-coercive decline path. |
| SEO metadata | Match visible page truth; avoid claims or keywords absent from the product experience. |

Do not change component behavior while performing a language task. If the correct wording needs a missing state, report a behavior-dependent blocker.
